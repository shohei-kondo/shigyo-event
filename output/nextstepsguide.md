# 第1部 概要

## 残り作業の全体像

| Step | 内容 | 担当 | 目安時間 |
|---|---|---|---|
| 1 | フォーム送信テスト＋スマホ実機確認（Phase 4 完了） | あなた | 15分 |
| 2 | フォーム送信者の変更（GAS修正 → 再デプロイ → 再テスト） | あなた（＋AI補助） | 30分 |
| 3 | ビルドコマンド入替＋BUILD_INFO.txt（再発防止改修） | Cursor → あなたが検収 | 30分＋検収5分 |
| 4 | 静的サイトへの移行（Astroアーカイブ化） | Cursor → あなたが検収 | 1〜2時間＋検収15分 |
| 5 | 定常運用（文言修正 → アップロード → 確認） | あなた | 都度5〜15分 |

## 流れと順序の理由

```
Step 1（送信テスト）──→ Step 2（送信者変更）──→ Step 3（再発防止）──→ Step 4（静的化）──→ Step 5（定常運用）
   今すぐ                  1と続けて実施          次のビルド前に         急がない・安定後に      以後ずっと
```

- **Step 1 が最優先**。フォームは営業の生命線であり、表示がきれいでも送信が通らなければ意味がない。
- **Step 2 は Step 1 とセットで**。送信者を変えたら同じテストをもう一度やるので、手順が温かいうちに。
- **Step 3 は「次に誰かがビルドする前」までに**。`npm run build` と `build:prod` の取り違え事故（報告書6-6）を仕組みで潰す。
- **Step 4 は急がない**。本番が安定していることを1〜2週間確認してからでもよい。完了すると以後は npm・ビルド不要になる。

## Step 2 に関する重要な前提（今回の追加認識）

- お礼メール・通知メールは **GASをデプロイしたGoogleアカウント** から送られる。
- コードは `GmailApp.sendEmail(..., { from: senderEmail })` 方式のため、送信者に指定できるのは
  **そのアカウントのGmailに「送信元アドレス」として登録済みのエイリアスだけ**。
- 送信者を変更したら **GASの再デプロイが必須**（コード変更はデプロイするまで本番に反映されない）。
- ⚠ **再デプロイ時の最大の罠**: 「新しいデプロイ」を選ぶと公開URL（`/exec`）が変わり、
  サイト側のフォーム送信先も更新＋再アップロードが必要になる。
  必ず「**デプロイを管理 → 既存デプロイを編集 → 新バージョン**」の手順で行う（URLが変わらない）。

# 第2部 ステップバイステップ詳細手順書

## Step 1: フォーム送信テスト＋スマホ実機確認

1. シークレットウィンドウで `https://shigyo-event.comet-event.com/forms/free-consultation/` を開く。
2. テストと分かる内容で送信する（氏名に「【テスト】」を含める。メールアドレスは自分の受信できるもの）。
3. 以下の3点を確認する:
   - [ ] Googleスプレッドシートの `free-consultation` タブに1行追加されている
   - [ ] 申込者アドレス宛に **お礼メール** が届く（迷惑メールフォルダも確認）
   - [ ] 管理者宛に **通知メール** が届く
4. 残り2フォーム（`/forms/venue-support/`・`/forms/script-support/`）も同様に1件ずつ送信・確認する
   （スプレッドシートのタブはフォームごとに分かれる）。
5. スマホ実機（できればWi-Fiオフのモバイル回線）で `https://shigyo-event.comet-event.com/lawyer/` を開き、
   数秒で表示されることを確認する。
6. テスト行はスプレッドシート上で背景色を付けるか、備考に「テスト」と記録しておく（削除してもよい）。

**NGだった場合**: フォーム画面のエラー表示のスクショ＋スプレッドシートの状態を添えて、
報告書とともにAIに相談する。サイト側（HTML/JS）とGAS側のどちらの問題かの切り分けから始まる。

## Step 2: フォーム送信者の変更（GAS再デプロイ）

### 2-1. 送信元アドレスの事前準備（新しい送信者がエイリアス未登録の場合のみ）

1. GASをデプロイしているGoogleアカウントのGmailを開く。
2. 設定（歯車）→「すべての設定を表示」→「アカウント」タブ →「他のメールアドレスを追加」。
3. 新しい送信者アドレスを追加し、確認メールで承認を完了させる。
4. ここで登録したアドレスだけが `senderEmail` に指定できる。

### 2-2. スクリプトの修正

1. https://script.google.com で該当プロジェクト（フォーム受信用GAS）を開く。
2. `Code.gs` 内の送信者設定（`senderEmail` / `senderName` を設定している箇所）を新しい値に変更する。
   場所が分からなければ、リポジトリの `gas/Code.gs` をAIに見せて「senderEmail の設定箇所」を
   聞けばすぐ特定できる。
3. **リポジトリ側の `gas/Code.gs` にも同じ変更を反映してコミットする**
   （コードの写しを本番と一致させておく。これがズレると次に直す人が古いコードを見て混乱する）。

### 2-3. 再デプロイ（URLを変えない手順・最重要）

1. GASエディタ右上「デプロイ」→「**デプロイを管理**」を選ぶ（「新しいデプロイ」ではない！）。
2. 既存のWebアプリのデプロイ行の **鉛筆アイコン（編集）** をクリック。
3. 「バージョン」を「**新バージョン**」に変更し、「デプロイ」を押す。
4. 表示されるURLが従来と同じ（`AKfycb...` の部分が不変）であることを確認する。

### 2-4. 確認テスト

1. Step 1 と同じ手順で無料相談フォームから1件テスト送信する。
2. 届いたお礼メール・通知メールの **送信者表示（差出人名とアドレス）** が新しい値に
   なっていることを確認する。

### もしURLが変わってしまった場合（リカバリ）

「新しいデプロイ」を作ってしまいURLが変わった場合は、サイト側の送信先も更新が必要:

1. `src/config.ts` の `FORM_ENDPOINT` を新URLに書き換えてコミット。
2. `npm run build:prod`（Step 3 実施後は `npm run build`）→ `dist/forms/` 配下を再アップロード。
3. Step 1 の送信テストをやり直す。
（静的化移行（Step 4）後は、各フォームHTML内のURLを直接置換 → 該当ファイルをアップロード。）

## Step 3: 再発防止改修（Cursorへ依頼）

### 依頼文（コピペ用）

> `fix/deploy-and-unpack` に以下を追加してください。
> 1. `package.json` のスクリプトを入れ替え: `build` を本番用（DEPLOY_TARGET=production）に、
>    GitHub Pages用は `build:pages` に改名。`.github/workflows/deploy.yml` には
>    `env: DEPLOY_TARGET: pages` を明示追加。
> 2. ビルド時に `dist/BUILD_INFO.txt`（ターゲット名とビルド日時）を出力する。
> 完了条件（コマンド出力を貼って証明すること）:
> `npm run build` → `grep -r "/shigyo-event/" dist/` が0件 かつ BUILD_INFO.txt に production、
> `npm run build:pages` → `/shigyo-event/` 付き かつ BUILD_INFO.txt に pages。
> コミットして origin にプッシュするところまでが完了です。

### あなたの検収（5分）

1. Cursorの報告にある完了条件のコマンド出力を確認する。
2. `npm run build` → `dist` をアップロードした際、ファイルマネージャー上で `BUILD_INFO.txt` を
   開いて `production` と書かれていることを確認できるようになる。
3. **以後、本番用ビルドのコマンドは `npm run build` に変わる**点を覚えておく（メモ推奨）。

## Step 5: 定常運用フロー（Step 4 完了後の日常）

**文言修正（最頻の作業）:**

1. VS Code等でサイトフォルダを開き、フォルダ内検索で対象文言を探す
   （全LP共通の文言は複数ファイルにヒットする → 全部置換。AIにコピペ依頼でも可）。
2. Git にコミット（記録を残す）。
3. 変更したファイルだけお名前.comへアップロード。
4. シークレットウィンドウで表示確認。

**フォームの送信先（GAS URL）変更:**

- README の対応表を見て、各フォームHTML内のURLを置換 → 該当ファイルをアップロード
  → 送信テスト1件。

**フォームの送信者変更:**

- 本書 Step 2 の手順を再実施（GAS修正 → 「デプロイを管理」から新バージョン → テスト）。

**大規模改修が必要になったら:**

- `astro-archive` ブランチの復活、またはその時点のツールでの作り直しをAIに相談。
  日常の同期は不要（アーカイブは移行日時点のスナップショットのままでよい）。
