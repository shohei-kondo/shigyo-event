# Step 2 改訂版: 送信者を別ドメインのアカウントに変更する手順（2026-07-07）

対象: フォーム受信GASの実行主体を、別ドメインのGoogleアカウント（以下「新アカウント」）に移す。

## 前提の整理（元ガイドとの差分）

- 元ガイドの Step 2 は「同一アカウント内でエイリアスを変える」前提だった。今回は**実行アカウントごと変える**ため、手順が異なる。
- コード（`gas/Code.gs`）の送信者設定はハードコードではなく**スクリプトプロパティ**（`SENDER_EMAIL` / `SENDER_NAME` / `REPLY_TO_EMAIL` / `SPREADSHEET_ID` / `OWNER_EMAIL`）。**コード自体の修正は不要**で、新プロジェクトに同じコードを貼るだけでよい。
- 新アカウントでデプロイし直すと **exec URL は必ず変わる**。サイト側の送信先更新＋アップロードまでがワンセット。
- 新アカウント自身が送信者になるため、**エイリアス登録は不要**（新アカウントの別名で送りたい場合のみ必要）。

## スプレッドシートは複製しなくてよい（推奨）

`SpreadsheetApp.openById()` は**編集権限があれば動く**。所有権は不要。

- **推奨**: 既存スプレッドシートを新アカウントに「編集者」で共有し、`SPREADSHEET_ID` は今のまま使う。過去の応募データと今後のデータが1つのファイルに残り続ける。
- 複製が必要になるのは「新ドメイン側にファイルの所有権を持たせたい」場合のみ（別ドメインへの所有権移転はできないため）。その場合は複製後の新IDを `SPREADSHEET_ID` に設定する。過去データはコピー時点のスナップショットになる点に注意。

## 手順

### A. 新アカウント側でGASを新規作成（20分）

1. 既存スプレッドシートを新アカウントへ「編集者」で共有（複製する場合はこの代わりに「コピーを作成」→新IDを控える）。
2. 新アカウントで https://script.google.com → 「新しいプロジェクト」（スタンドアロンでよい。シートから開く必要なし）。
3. リポジトリの `gas/Code.gs` の中身を**そのまま全文**貼り付け、保存。
4. プロジェクトの設定（歯車）→「スクリプト プロパティ」に以下を設定:
   - `SPREADSHEET_ID` … 既存（共有した）シートのID ※複製したなら新ID
   - `OWNER_EMAIL` … 通知メールの宛先（カンマ区切りで複数可）
   - `SENDER_NAME` … 差出人表示名（未設定なら「イベント幹事サポート」）
   - `SENDER_EMAIL` … **設定しない**（新アカウント自身から送るなら不要。設定すると
     そのアカウントのGmailエイリアス登録済みアドレスしか受け付けず、未登録だと送信が全部エラーになる）
   - `REPLY_TO_EMAIL` … 返信を受けたいアドレス（任意）
5. デプロイ → 「新しいデプロイ」→ 種類「ウェブアプリ」:
   - 実行ユーザー: **自分**
   - アクセスできるユーザー: **全員**
6. 承認フローを完了し、新しい `/exec` URL を控える。
7. ブラウザで新URLを直接開き、`{"ok":true,"service":"shigyo-event-form","spreadsheetConfigured":true,"ownerConfigured":true,...}` が返ることを確認（doGetヘルスチェック。`false`があればプロパティ名のタイポを疑う）。

### B. サイト側の送信先を新URLへ変更（15分）

**まだAstroビルド運用の場合:**

1. `src/config.ts` の `FORM_ENDPOINT` を新URLに書き換えてコミット。
2. `npm run build:prod`（Step 3実施後なら `npm run build`）。
3. `dist/forms/` 配下（3フォーム）をお名前.comへアップロード。

**dist直接編集運用に移行済みの場合:**

1. `forms/free-consultation/index.html`・`forms/venue-support/index.html`・`forms/script-support/index.html` 内の
   旧URL（`AKfycbzcCfZX...` を含む `/exec` URL）を新URLに一括置換。
2. 3ファイルをアップロード。
3. リポジトリ側の `src/config.ts` にも同じ変更をコミット（写しの一致を保つ）。

### C. 確認テスト（15分）

1. シークレットウィンドウで3フォームそれぞれから「【テスト】」付きで1件送信。
2. 確認3点セット:
   - [ ] スプレッドシートの各タブに行が追加される
   - [ ] お礼メールの**差出人が新アカウント（新ドメイン）**になっている
   - [ ] `OWNER_EMAIL` 宛に通知メールが届く
3. 迷惑メール判定も確認（送信ドメインが変わるため初回は要注意。新ドメインの
   SPF/DKIM が未整備だと迷惑行きしやすい。Gmail送信なら通常は問題ないが、届かなければここを疑う）。

### D. 後始末（5分）

1. 数日安定稼働を確認後、旧アカウントのGAS: デプロイを管理 → 旧デプロイを**アーカイブ**（無効化）。
   ※すぐ消さない。切り戻し先として残す。
2. `gas/README.md` 等に「実行アカウント・デプロイURLを変更した」旨と日付を追記してコミット。

## 切り戻し

新URLで問題が出たら、サイト側のURLを旧 `/exec` に戻してアップロードするだけで即復旧（旧GASをアーカイブする前なら生きている）。

## よくある失敗

| 症状 | 原因 |
|---|---|
| 送信すると「SENDER_EMAIL is not configured as a Gmail sending alias」 | `SENDER_EMAIL` に未登録アドレスを設定した → プロパティを削除するか、新アカウントのGmailでエイリアス登録 |
| シートに書き込まれない | 共有し忘れ／`SPREADSHEET_ID` の写し間違い |
| フォームがエラーになる | デプロイ設定が「全員」になっていない／URLの貼り間違い |
| メールが届かない（エラーなし） | 迷惑メールフォルダ、`SEND_USER_COPY=false` の設定残り |
